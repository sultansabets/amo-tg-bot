# amo-tg-bot

Production-ready Node.js Telegram bot that monitors amoCRM leads and notifies responsible managers when:

1. **Lead is stale** — sits in a pipeline stage longer than `STALE_LEAD_MINUTES`.
2. **Client message is unanswered** — incoming note (type `102`/`25`) hasn't been replied to (type `103`/`10`) within `UNANSWERED_MESSAGE_MINUTES`.

Stack: Node.js · Express · Telegraf (long-polling) · better-sqlite3 · node-cron · axios.

---

## 1. Ubuntu VPS setup

```bash
# 1. Install Node.js 20 LTS
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs build-essential git

# 2. Install PM2
sudo npm install -g pm2

# 3. Clone & install
git clone <your-repo> amo-tg-bot
cd amo-tg-bot
cp .env.example .env
nano .env                 # fill in values
npm install

# 4. Open firewall for the port (default 3000)
sudo ufw allow 3000/tcp

# 5. Start with PM2
pm2 start ecosystem.config.js
pm2 save
pm2 startup            # follow the printed command to enable boot autostart
```

## 2. Find amoCRM `user_id`

Open amoCRM → **Settings → Users** → click a manager. The numeric ID is in the URL:

```
https://company.amocrm.ru/settings/users/USER_ID/
```

Each manager runs `/start` in Telegram (to learn their chat_id), then `/addme <USER_ID>` to bind themselves.

---

## 3. Create amoCRM integration (OAuth credentials)

amoCRM → **Settings → Integrations** → **Create integration** → "Внешняя интеграция".

- **Redirect URI**: `http://YOUR_IP:PORT/amo/oauth` (must match `AMO_REDIRECT_URI`).
- Grant scopes: leads, contacts, notes, tasks (read access is sufficient).
- Save. Copy the **Integration ID** (`AMO_CLIENT_ID`) and **Secret key** (`AMO_CLIENT_SECRET`).

---

## 4. Webhook events to subscribe in amoCRM

In the integration → **Webhooks** tab, add the webhook URL:

```
http://YOUR_IP:PORT/amo/webhook/<WEBHOOK_SECRET>
```

Subscribe to:

- **Сделки**: добавление, изменение, изменение этапа, удаление
- **Примечания**: добавление (notes / messages — needed for incoming/outgoing note types `102`, `25`, `103`, `10`)

---

## 5. Get the first OAuth token

1. With the bot running, open the **authorization URL** generated by amoCRM in the integration page (it ends with `?client_id=...&state=...&mode=post_message`). Or use the standard OAuth URL:

   ```
   https://www.amocrm.ru/oauth?client_id=AMO_CLIENT_ID&state=x&mode=post_message
   ```

2. Click **Allow**. amoCRM redirects to `AMO_REDIRECT_URI` (= `http://YOUR_IP:PORT/amo/oauth?code=...`).
3. The bot exchanges the code for `access_token`/`refresh_token` and stores them in SQLite.
4. You should see `✅ Токен получен` in the browser and `✅ amoCRM OAuth: tokens stored` in PM2 logs.

After that the bot auto-refreshes tokens (60-second buffer before expiry, plus on-401 retry).

> If you obtained a long-lived token through the integration page directly, you can also paste it as `AMO_ACCESS_TOKEN` + `AMO_REFRESH_TOKEN` in `.env`. The DB always wins over `.env` once OAuth runs.

## 6. SQLite inspection

```bash
sqlite3 data/bot.sqlite

.tables
.schema stage_tracking

SELECT lead_id, stage_name, datetime(entered_at,'unixepoch','+5 hours') AS entered_almaty,
       datetime(last_notified_at,'unixepoch','+5 hours') AS last_notified
FROM stage_tracking ORDER BY entered_at DESC LIMIT 20;

SELECT * FROM message_tracking WHERE notified=0;
SELECT * FROM user_mapping;
SELECT lead_id, type, success, datetime(sent_at,'unixepoch','+5 hours') AS sent
FROM notification_log ORDER BY id DESC LIMIT 20;
```

## Telegram commands

| Command | Description |
|---|---|
| `/start` | Welcome message + your `chat_id` |
| `/addme <amo_user_id>` | Bind yourself to an amoCRM user |
| `/whoami` | Show your current binding |
| `/list` | List all active bindings |
| `/status` | Counters + active thresholds |
| `/test <lead_id>` | Fetch a lead and send a sample notification to yourself |

Any non-command message from an unbound user echoes their `chat_id` and prompts `/addme`.
